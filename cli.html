CLI Reference ​

cloding ​

Start an interactive coding session or run a single prompt.

bash
cloding [options]

Options ​

FlagDescriptionExample
-m, --model <name>Model shortcut or OpenRouter model IDcloding -m sonnet
-p, --prompt <text>Run a single prompt (non-interactive)cloding -p "fix the bug"
--list-modelsShow all available models with pricingcloding --list-models
-v, --versionShow cloding versioncloding -v
-h, --helpShow help messagecloding -h

All additional flags are passed through to the underlying CLI tool.

Model Suffixes ​

SuffixProviderExample
(none) or -oOpenRoutercloding -m sonnet
-aDirect APIcloding -m sonnet-a
-pPaid plancloding -m sonnet-p

Examples ​

bash
# Interactive session with default model (Qwen 3 Coder)
cloding

# Use a specific model shortcut
cloding -m haiku

# Use direct Anthropic API
cloding -m sonnet-a

# Use Claude Max subscription
cloding -m opus-p

# Use Codex via ChatGPT plan
cloding -m codex-5

# Use Gemini via Google API
cloding -m gemini-3-a

# Use GitHub Copilot
cloding -m copilot

# Single prompt, non-interactive
cloding -p "add dark mode to the settings page"

# Any OpenRouter model by ID
cloding -m meta-llama/llama-4-scout

# Combine model selection with a prompt
cloding -m sonnet-a -p "review src/auth.ts for security issues"

# Pass through CLI tool flags
cloding --allowedTools Read,Write,Bash

cloding docker ​

Manage Docker-sandboxed sessions. See Docker Mode for full documentation.

Subcommands ​

CommandDescription
cloding docker buildBuild the Docker image (one-time setup)
cloding docker shellStart an interactive sandboxed session
cloding docker run <prompt>Run a prompt in a container
cloding docker statusShow running cloding containers
cloding docker stopStop all cloding containers
cloding docker cleanRemove stopped containers and free disk space

Docker Run Options ​

FlagDescriptionDefault
-m, --model <name>Model to useqwen
-w, --workspace <path>Workspace directory to mount. (current directory)
--memory <limit>Memory limit (e.g., 4g, 512m)No limit
--cpus <count>CPU limit (e.g., 2, 0.5)No limit
--name <name>Custom container nameAuto-generated
--no-rmKeep container after exitAuto-remove
--no-cacheRebuild image without Docker cache—

Examples ​

bash
# Build the Docker image
cloding docker build

# Interactive sandboxed session
cloding docker shell

# Run a prompt in a container
cloding docker run "fix the bug in src/api/users.ts"

# Specific model with workspace
cloding docker run -m sonnet-a -w ./myproject "add input validation"

# Different tools in Docker
cloding docker run -m codex-5 "debug my tests"
cloding docker run -m opus-p "architecture review"

# Resource-limited execution
cloding docker run --memory 4g --cpus 2 "refactor the auth module"

# Check running containers
cloding docker status

# Clean up after a session
cloding docker stop && cloding docker clean

cloding pipeline ​

Run multi-stage coding pipelines. See Pipeline Mode for full documentation.

bash
cloding pipeline <prompt> [options]

Options ​

FlagDescriptionDefault
-c, --config <path>Pipeline config YAML fileconfigs/default.yaml
-w, --workspace <path>Project workspace directory.
-f, --file <path>Read request from file—
--context-files <files>Comma-separated list of key files—
--no-dockerRun without Docker isolation—
--no-gitSkip git workspace preparation—
--dry-runPrint pipeline config and exit—
--resume <stage>Resume from a specific stage—
--run-id <id>Run ID to resume from—
--prompts-dir <dir>Prompt templates directoryprompts
-v, --verboseEnable debug logging—

Examples ​

bash
# Standard pipeline with default config
cloding pipeline "Add user authentication" --workspace ./myapp

# Without Docker for faster iteration
cloding pipeline "Add auth" --workspace ./myapp --no-docker

# Custom pipeline config
cloding pipeline -c configs/qwen-fanout.yaml "Refactor the DB layer"

# Dry run — show config without executing
cloding pipeline --dry-run -c configs/default.yaml "anything"

# Resume from a specific stage
cloding pipeline --resume code --run-id <run-id> "original request"

Exit Codes ​

CodeMeaning
0Success
1General error (invalid arguments, runtime failure)
2API key missing or invalid
3Model not found
130Interrupted (Ctrl+C)

Exit codes are useful for scripting and CI/CD integration:

bash
cloding -p "run the test suite" || echo "cloding failed with exit code $?"

Environment Variables ​

These environment variables affect cloding's behavior. See Configuration for details.

VariableDescription
OPENROUTER_API_KEYYour OpenRouter API key
CLODING_DEFAULT_MODELDefault model shortcut (default: qwen)
ANTHROPIC_API_KEYDirect Anthropic API key (for -a variants)
GOOGLE_API_KEYDirect Google API key (for gemini-3-a)
OPENAI_API_KEYDirect OpenAI API key (for codex-5-a)
GITHUB_TOKENGitHub PAT (for copilot)
