Contributing ​

Thanks for your interest in contributing to cloding. This guide covers everything you need to get started.

Development Setup ​

Prerequisites ​

  • Node.js 18+ (Node.js 24+ for Copilot CLI)
  • Git
  • At least one CLI tool installed (Claude Code is the default)

Clone and Install ​

bash
git clone https://github.com/claudlos/cloding.git
cd cloding
npm install

Run Locally ​

bash
# Run cloding from source
node bin/cloding.js

# Run with arguments
node bin/cloding.js -m haiku -p "hello"

# Test Docker mode
node bin/cloding.js docker build
node bin/cloding.js docker run "test"

Run Pipeline Tests ​

bash
cd pipeline && pip install -r requirements-dev.txt
cd pipeline && pytest tests/ -v -p no:anchorpy    # 174 tests
cd pipeline && pytest tests/ --cov=cloding --cov-report=term-missing  # Coverage

Project Structure ​

cloding/
├── bin/
│   └── cloding.js              # CLI entry point (~850 lines)
├── models.json                 # Model shortcuts, IDs, tools, pricing
├── pipeline/
│   ├── cloding/                # Python pipeline package
│   │   ├── core/               # Config, errors, logger, workspace
│   │   ├── pipeline/           # Stages, sequencer, state
│   │   ├── runners/            # Local + Docker runners
│   │   ├── fanout/             # Task splitting, parallel execution
│   │   ├── models/             # Model registry, cost tracking
│   │   └── cli/                # Pipeline CLI entry point
│   ├── configs/                # 9 built-in pipeline configs
│   ├── prompts/                # Stage prompt templates
│   ├── docker/                 # Dockerfile + docker-compose
│   └── tests/                  # 174 async tests
├── package.json
└── README.md

Key Files ​

How to Contribute ​

Bug Reports ​

Found a bug? Open an issue with:

  • What happened — The actual behavior
  • What you expected — The expected behavior
  • Steps to reproduce — Commands you ran
  • Environment — OS, Node.js version, cloding version
bash
# Include this info in your bug report
node --version
npm list -g cloding
claude --version

Feature Requests ​

Have an idea? Open an issue describing:

  • The problem — What workflow is painful or missing?
  • Proposed solution — How should it work?
  • Alternatives — Other approaches you considered

Pull Requests ​

  1. Fork the repo and create a feature branch from master
  2. Make your changes with clear, focused commits
  3. Add tests for new functionality
  4. Update docs if your change affects user-facing behavior
  5. Open a PR with a clear description of what changed and why

Small PRs are better

A focused PR that does one thing well is easier to review and more likely to be merged quickly than a large PR that changes everything.

Code Style ​

  • JavaScript — Zero dependencies, vanilla JS, CommonJS require. No build step.
  • Python — Line length 100 (black), type hints, Google-style docstrings
  • Markdown — Use ATX headings (#), fenced code blocks with language tags
  • Commits — Clear, descriptive messages. Start with a verb: "Add", "Fix", "Update", "Remove"

Adding a New Model Shortcut ​

To add a new built-in model shortcut:

  1. Add the entry to models.json:
json
{
  "new-model": {
    "id": "provider/model-id",
    "name": "Model Display Name",
    "tool": "claude",
    "provider": "openrouter",
    "in": 1.00,
    "out": 2.00
  }
}
  1. Test that it works: node bin/cloding.js -m new-model -p "hello"
  2. Update the docs models page
  3. Open a PR

Adding a New Tool ​

To add support for a new CLI tool:

  1. Add tool handler in pipeline/cloding/core/tool_handler.py
  2. Add model entries in models.json with the new tool value
  3. Update bin/cloding.js to handle the new tool's spawning
  4. Update Docker image to include the new CLI
  5. Add tests and docs
  6. Open a PR
