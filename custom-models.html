Custom Models ​

cloding ships with built-in shortcuts for popular models, but you can add your own by editing the models.json file.

models.json Format ​

The models.json file maps shortcut names to model configuration:

json
{
  "my-model": {
    "id": "provider/model-id",
    "name": "My Model",
    "tool": "claude",
    "provider": "openrouter",
    "api_key_env": "OPENROUTER_API_KEY",
    "in": 0.50,
    "out": 1.50
  }
}

Fields ​

FieldRequiredDescription
idYesOpenRouter model ID or provider model ID
nameYesDisplay name shown in --list-models
toolNoCLI tool to use: claude (default), gemini, codex, copilot, opencode
providerNoAuth provider: openrouter (default), anthropic, plan, google, openai, github
api_key_envNoEnvironment variable for the API key
inNoInput cost in $/Mtok (for display only)
outNoOutput cost in $/Mtok (for display only)

Adding a Model ​

To add a new model shortcut, add an entry to models.json:

json
{
  "llama": {
    "id": "meta-llama/llama-4-scout",
    "name": "Llama 4 Scout",
    "tool": "claude",
    "provider": "openrouter",
    "in": 0.15,
    "out": 0.60
  },
  "grok": {
    "id": "x-ai/grok-3",
    "name": "Grok 3",
    "tool": "claude",
    "provider": "openrouter",
    "in": 3.00,
    "out": 15.00
  }
}

Then use it:

bash
cloding -m llama
cloding -m grok

Adding a Direct Tool Model ​

You can also add models that use non-Claude tools:

json
{
  "my-gemini": {
    "id": "gemini-2.5-pro",
    "name": "My Gemini Setup",
    "tool": "gemini",
    "provider": "google",
    "api_key_env": "GOOGLE_API_KEY",
    "in": 0.0,
    "out": 0.0
  }
}

Supported tool values ​

ValueCLI Tool
claudeClaude Code (default)
geminiGemini CLI
codexCodex CLI
copilotGitHub Copilot CLI
opencodeOpenCode

Supported provider values ​

ValueAuth Mode
openrouterOpenRouter API (default)
anthropicDirect Anthropic API
planPaid subscription (no API key)
googleDirect Google API
openaiDirect OpenAI API
githubGitHub token

Finding Model IDs ​

Browse available OpenRouter models at openrouter.ai/models. The model ID is the string shown in the model's URL and API reference — for example, meta-llama/llama-4-scout.

TIP

You don't need to add models to models.json to use them. You can always pass any OpenRouter model ID directly with -m:

bash
cloding -m meta-llama/llama-4-scout

The models.json shortcuts are just for convenience and to show pricing in --list-models.

Models That Support Tool Use ​

Claude Code relies heavily on tool use (function calling) to edit files, run commands, and interact with your codebase. Not all models support tool use well.

Models without tool use support

If a model doesn't support tool use, Claude Code will fall back to a text-only mode where it can't edit files or run commands. This defeats the purpose of using cloding.

Before adding a custom model, check its OpenRouter page for "Function calling" or "Tool use" support.

Models known to work well with tool use:

ModelTool UseNotes
Qwen 3 CoderYesExcellent tool use support
DeepSeek V3.2YesStrong tool use
Claude (all versions)YesNative tool use
Gemini 2.5 ProYesGood tool use
CodexYesGood tool use
Mistral LargeYesGood tool use
Llama 4 ScoutPartialWorks but less reliable
Smaller/older modelsNoOften lack tool use

Testing Your Model ​

After adding a custom model, test it with a simple prompt:

bash
# Quick smoke test — can it read and edit a file?
cloding -m my-model -p "read package.json and add a 'hello' script that runs 'echo hello'"

What to check:

  • Does the model successfully read the file?
  • Does it produce a valid edit?
  • Does it run the correct terminal commands?

If the model struggles with basic file operations, it may not support tool use well enough.

Cost Fields ​

The in and out fields in models.json are in dollars per million tokens ($/Mtok). These values are used for display in --list-models output. They don't affect routing or billing — the provider handles actual pricing. Keep them accurate for your own reference.

models.json Location ​

The models.json file is located in cloding's installation directory. To find it:

bash
npm list -g cloding
# Navigate to the package directory and find models.json

INFO

Changes to models.json persist across sessions but may be overwritten when you update cloding (npm update -g cloding). Keep a backup of your custom models if you've added any.
